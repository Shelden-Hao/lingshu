# Texts and languages in p2

p2's web UI is written in English in code and rendered in the reader's language: English or Chinese today, and any
other language a catalog later adds. The machinery is Chord's app kit (`packages/chord/docs/i18n/book.md`, `design.md`
§23); this page is what p2 applies on top of it.

## What exists

- **A plugin's texts live in its `messages.ts`**, one catalog per language, `en` first:

  ```ts
  // plugins/settings/messages.ts
  import { defineMessages } from "@p2/app/v1";

  export const messages = defineMessages("settings", {
      en: { title: "Settings", language: "Language" },
      zh: { title: "设置", language: "界面语言" },
  });
  ```

  `en` defines the keys and their argument types; a key missing from `zh`, an unknown key or a wrong argument is a
  compile error.

- **The web facet contributes the catalogs**, so a page uses them and a translation plugin can override them:

  ```ts
  export default defineFacet((host, self) => {
      self.contribute(Translations, messages.translations);
      // ... the facet's own contributions
  });
  ```

- **A component renders with `useMessages`** (`@p2/app/v1/web`): `const { t } = useMessages(messages)`, then
  `t("title")`. It re-renders when the reader picks another language or a translation arrives.

- **p2's own texts** (the app frame, the sheets, the command menu's own words) are in `src/web/messages.ts`, namespace
  `p2`, contributed by the web core facet (`src/runtime/web-core.ts`).

- **Language choice** is a per-user preference the server keeps (`src/hosts/server.ts` serves Chord's
  `chord.locale.choice`): Settings → Language (`plugins/settings/web.tsx`) lists the locales some catalog offers and
  writes the pick; `null` follows the device's language. A pick re-renders every page of that user, without a reload.

## Texts a registry carries

A command's title, a Settings section's label, a menu page's placeholder: registries hold these as a `ContributedText`
(`src/runtime/web-core.ts`), not as a final string, because a contribution is made once and read in whichever language
the reader uses.

- **Translated:** `textIn(messages, "showSidebar")` renders the plugin's own message in the reader's language (and
  applies a translation plugin's override).
- **Not translated yet:** a plain string stays as it is, which is what a plugin that has not been translated yet
  contributes.
- **Reading one:** `showText(text, language)`, where `language` comes from `useLanguage()`.

## What is never translated

- The model's own words, prompts and logs (English, for developers).
- Locale-independent identifiers: model ids, setting values, serialized state.
- The server-rendered pages (`src/runtime/page.ts`: sign-in, join) still say English: they are written before any
  language preference is known. Translating them means reading `Accept-Language` there; not done yet.

## Adding a language

A new plugin (or a translation plugin) contributes `{ namespace, locale, messages }` to `Translations`. The Settings
window lists it as soon as a catalog offers it; nothing else changes.

## Checking it

- `npm run check` in `apps/p2` (types and Biome): a missing or mistyped key fails it.
- Browser tests (`test/p2/ui-*.test.ts`) need Chromium (`CHROMIUM_BIN`) and Node 26.
